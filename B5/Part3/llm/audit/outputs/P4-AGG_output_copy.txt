## 8. Cross-language observations

The implementations illustrate different language mechanisms rather than different business requirements.

Java and C++ use explicit interfaces and types extensively. Python employs standard-library abstractions and duck typing where suitable. JavaScript expresses shared contracts through compatible methods and callbacks.

The Adapter and Controller examples generally need more production code because they contain additional participant types, validation and coordination. Observer is comparatively compact across all four languages.

Python and JavaScript often express these examples in fewer production lines than Java and C++, but fewer lines do not automatically imply better maintainability. Similarly, the observed timing differences cannot establish which language is inherently better for a given pattern.

The complete report discusses all five collaborations individually, including C++ observer-pointer lifetime assumptions and the distinction between Adapter's source-format translation and Strategy's interchangeable algorithms.

## 11. Remaining limitations

The twenty implementations are deliberately small, fixture-driven demonstrations. They do not reproduce Rails, persistence, Anthropic generation, live geocoding/Turbo, external provider APIs, real mail delivery or booking cancellations.

LOC and complexity are source-based measurements; benchmark medians are specific to the recorded machine and full process workload. Neither should be used alone to rank design quality.

DaPlanStan's full Rails integration/regression testing remains outstanding because the previously available environment used Ruby 3.3.8 instead of the required Ruby 3.4.2 and lacked the locked Rails 8.1.3 dependencies.
