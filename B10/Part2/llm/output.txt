CHANGE 1 (CH01) - Add new crop types
------------------------------------
Starting point check. The suggestion fits. bang_bang.CustomModule (mycodo/functions/bang_bang.py) is
an on/off hysteresis controller. With direction 'raise' and a soil-moisture measurement it switches an
irrigation output on when the soil is dry, and its setpoint and hysteresis are exactly what a crop
profile should supply. Caveat: bang_bang.py:17 has the TODO "Remove this at next major version
(obsolete because a On/Off Raise/Lower/Both Bang-Bang exists)", which points to
functions/bang_bang_on_off.py. We still use bang_bang.py because it is the Part 1 scope file and the
suggested starting point (see Risks).

Step a (commit dee5d7d76). test_bang_bang_characterization.py has 25 tests, one of them parametrised
over 15 decision cases. They build the real CustomModule (DB and daemon mocked) and lock in:
- option parsing and the output-channel lookup;
- get_last_measurement(device, measurement, max_age=...);
- every on/off decision for 'raise' and 'lower', including the non-inclusive band edges, output_on
  being re-sent while the output is already on, and output_off only when the output is on;
- [ts, None] → output off with the exact error text;
- unknown direction → error only;
- missing output channel → early return;
- the timer gate and whole-period timer advance;
- stop_function.
All 25 passed on the unchanged code.

Step b (commit d454803d0)
- Smell: Duplicated Code. loop() computed the band edges four times: `self.setpoint + self.hysteresis`
  at bang_bang.py:188 and :205, and `self.setpoint - self.hysteresis` at :194 and :199 (baseline lines,
  checked with grep -n).
- Fowler technique: Extract Method → `_lower_threshold()`, `_upper_threshold()`.
- The 25 tests passed unchanged.
- Why this smell: CH01 changes where setpoint and hysteresis come from, so the band calculation should
  exist in exactly one place.

Step c (commit bdc43f9a3)

Step c (commit 9e3d56e8d)
- New strategies:
  - TimeWindowStrategy: irrigate only inside HH:MM-HH:MM windows; windows may cross midnight; start
    inclusive, end exclusive; a running pump is switched off outside the windows.
  - RainSkipStrategy: skip while the rain indicator is at or above the threshold; a running pump is
    switched off; a missing reading falls back to the band with a warning.
  - Both derive from IrrigationRestriction, which holds `inner` and delegates. That makes them stackable
    decorators around either direction.
- Single creation point: build_irrigation_strategy(name, direction, ...), plus parse_time_windows and
  in_time_windows.
- bang_bang.py:
  - five new optional options;
  - initialize() builds self.strategy through _build_irrigation_strategy(). An unknown strategy,
    invalid windows, or skip_if_rain without a rain measurement is logged and falls back to
    'hysteresis', so the crop is never left unwatered by a configuration error;
  - loop() passes `now` (from _now(), which tests can override) and the rain indicator (read by
    _read_rain_indicator() only if strategy.needs_rain_indicator()).
- Tests AC1-AC9 (test_ch02_irrigation_strategies.py): 64/64.
- Mutation check: bypassing the time-window test made AC2, AC3 and AC8 fail (file restored before the
  commit).

Unsure / decisions (CH02)
- Strategy and Decorator are both reported. One could argue the restrictions are "just more
  strategies". I count the Decorator separately because the defining relation is different (wrapper
  holds a component of the same interface and adds behaviour). It also genuinely enables stacking (AC8).
  If the team prefers one instance, merge it into "Irrigation Decision Strategy" as "extended".
- Strategy status is reported per change as newly_introduced, although its first two concrete
  strategies already appear in the step-b commit. The step-c additions are new participants of the same
  collaboration, not a second instance.
- Rain data: no bundled Mycodo weather Input provides precipitation (checked
  weather_openweathermap_weather.py and weather_openweathermap_onecall.py measurement dicts). The
  strategy therefore accepts any selected measurement plus a threshold, and the UI phrase says so.
- Fail-safe choices: on invalid configuration or a missing rain reading, the controller keeps
  irrigating by the band rather than stopping. This is a domain decision the team may want to reverse.
- The UI only offers one strategy at a time (a select). Stacking is available at the API level (AC8)
  but is not exposed as a UI option, to keep the option set small.

Unsure / decisions (CH03)
- Alerts are edge-triggered (once per episode) rather than repeated every update period (default 5 s).
  Reason: e-mail flooding. Mycodo's hourly e-mail limit (utils/actions.check_allowed_to_email) was not
  reused, because importing mycodo.utils.actions pulls in mycodo.devices.camera and DB writes, which
  would add heavy imports to bang_bang. Edge-triggering plus the existing SMTP settings is the lighter
  choice. Risk: a restart re-arms the alerts, because the active state is in memory only.
- "Critically dry" uses `measurement < alert_critical_moisture` for both directions. That is meaningful
  for irrigation ('raise'); for a 'lower' controller the alert is simply "below the critical level".
- DaemonControl.send_email is a static method that runs locally (SMTP from the settings DB), not through
  the daemon. That is why the Proxy instance gains no participant.
- Part 1 had "Observer - Output trigger notification" as UNCERTAIN (base_output.check_triggers). That
  candidate is unaffected; the new Observer is a separate, newly introduced collaboration.

RISKS AND LIMITATIONS
---------------------
1. Baseline names. The verified Part1/patterns.csv and Part1/Pattern_count.csv were not available, so
   the unverified Part 1 LLM draft is the baseline (D1). If the team's verified list differs (renamed,
   merged, rejected or added instances), all "Pattern effects" tables, .mmd headers and both
   *_llm_draft.csv files need the same correction. The Part 1 draft itself flags the Command instance
   and the six-way Template Method split as debatable.
2. Test environment. All tests run on Windows without a Mycodo installation:
   - grp/pwd are stubbed;
   - the settings DB, the daemon (DaemonControl) and InfluxDB reads (get_last_measurement) are
     replaced by unittest.mock.
   The tests therefore prove the decision logic and the wiring inside bang_bang.py, not the end-to-end
   behaviour in a running daemon (option forms in the web UI, the real Pyro5 calls, real SMTP). The
   upstream suite mycodo/tests/software_tests was not run.
3. UI integration not verified. The new options use only existing option types (select, text, float,
   integer, select_measurement), but the rendering in the Flask Function page was not checked. The
   crop and strategy choices are computed when bang_bang.py is imported; a crop registered later at run
   time is usable by id but does not appear in the UI list until restart.
4. The module is marked obsolete. bang_bang.py:17 says the module will be removed at the next major
   version in favour of functions/bang_bang_on_off.py. The features would then have to be ported. The
   new plain modules (crop_profiles, irrigation_strategies, sensor_alerts) are independent of bang_bang
   and can be reused by bang_bang_on_off.py.
5. Domain assumptions.
   - Crop values are illustrative.
   - Crop targets assume a percent moisture measurement, which needs rescaling for raw sensors.
   - No bundled weather Input provides rain or precipitation, so skip_if_rain relies on a user-selected
     indicator.
   - Fail-safe fallbacks keep irrigating by the band on configuration errors or a missing rain reading.
   - The "critically dry" comparison is `<` for both directions.
6. Alert delivery.
   - Alerts are edge-triggered with the state held in memory, so a daemon restart re-arms them.
   - Mycodo's hourly e-mail cap (check_allowed_to_email) is not applied.
   - E-mail is sent synchronously inside loop(). A slow SMTP server delays that control period;
     failures are caught and logged.
7. Pattern-status judgement calls.
   - "modified" is used whenever code inside a role changed or moved (strict rule), e.g. the Proxy
     client. A reader could call some of these "preserved".
   - Strategy and Decorator are counted as two instances over the same classes. They could be merged
     ("extended").
   - The crop catalogue is not counted as any pattern.
8. Behaviour changes that are intended, not refactorings.
   - CH03 fixes the baseline defect: a None / [] measurement now turns the output off instead of
     raising.
   - The initialize() log line gained the crop and strategy.
   - output_on is still re-sent every period while the measurement is below the band (characterized
     original behaviour, kept on purpose).
9. Metrics. lizard counts only the files in metrics_files.txt (24 scope files + 3 new modules; tests
   excluded). Max CCN stays at 51 (base_output.output_on_off, untouched). Averages move only slightly,
   because the changed file is 1 of 27.
10. Line endings. Part2/work uses core.autocrlf=true (system setting in C:/Program Files/Git/etc/gitconfig). Git
    warned about LF→CRLF on new files; the diffs are unaffected.
